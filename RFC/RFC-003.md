## Summary

Issue #3 was originally opened by @CandelaGreen questioning whether the project's license was truly open source due to commercial restrictions. @bouclem (project owner) resolved the license question immediately ("licenses done").

The discussion then evolved into several related topics that remain open:

1. **Finetuning strategy** — which base models to finetune for Project-4o
2. **GPT-4o dataset collection** — how to gather and consolidate GPT-4o conversation data
3. **Vibe benchmark** — @bouclem's idea for a "4o-like vibe" benchmark
4. **Model preservation framework** — @CandelaGreen's idea for a GPT-4o profile and Project-4o variants
5. **Small LLM family** — @CandelaGreen's proposal to base Project-4o on a small LLM family

Nothing is decided yet. This RFC captures the discussion points for community input.

## 1. Finetuning Strategy

### @AonzOG's proposals

@AonzOG suggested several candidate base models for finetuning, ranging from small CPU-compatible models to larger MoE models:

| Model | Size | Notes |
|-------|------|-------|
| GPT-OSS pruned to 9B | ~9B | Start by finetuning 4o datasets into this |
| Qwen3.5-35B-A3B | 35B (3B active) | MoE, possible starting point |
| MiniCPM-o-4.5 | — | Smaller vision or omni-modal option |
| LFM2-V-1.6B | 1.6B | CPU-compatible edge vision LLM, low compute |
| LFM2.5-VL-450M | 450M | Very small, good for testing finetuning viability on low compute |

@AonzOG also suggested a potential omni-modal path:
- GPT-OSS-9B as base
- Add SigLip2 400M for vision
- Add Whisper Medium + CosyVoice2 for audio
- Result: "GPT-OSS-9B-Omni"

@AonzOG's reasoning for starting small:

> Perhaps we can consider finetuning a smaller model that works well in CPU like LFM2.5-VL-450M. It's based on the LFM2.5-350M backbone which actually does a great job of having GPT-4o type personality with appropriate custom system prompt and memory RAG pipeline.

### @bouclem's response

@bouclem acknowledged the idea and indicated they will work on something. Data contributions via PR are welcome:

> i think it an good idea, but i'll make something, also if you want to give data you can do by doing PR

### Open questions

- Which base model should Project-4o finetune first?
- Should the project start with the smallest viable model (LFM2.5-VL-450M) to test on low compute?
- Should the project target omni-modal from the start, or text-first then add modalities?
- How does model choice interact with @bouclem's compute constraints (16GB VRAM, AMD ROCm)?

## 2. GPT-4o Dataset Collection

### @AonzOG's proposals

- **Consolidate GPT-4o conversation datasets** as the core training data
- **500 to 5000 conversations** may be enough to get GPT-4o-like behaviour from a small model like LFM2-V-1.6B
- **Generate fresh datasets** using DeepSeekV4 as a user communicating with GPT-4o via API in an AI Arena inferencer
- **PR-based donations** — community members can donate chat sessions as contributions
- **Anonymisation** — need tools for anonymising donated conversations

> Anyone knows any good anonymiser tools?

### Open questions

- How many GPT-4o conversations are needed minimum?
- What format should donated datasets follow?
- Which anonymiser tools should be used?
- Is using DeepSeekV4 + GPT-4o API for dataset generation legally and ethically acceptable?
- How should dataset provenance and licensing be tracked?
- Should there be a dataset registry or standard format for contributions?

## Progress Update (September 2026)

### Model selected

After surveying 1-3B parameter models on Hugging Face (2026 releases), the following base model was chosen:

- **Base model:** `openbmb/MiniCPM5-1B-SFT` (1B params, SFT checkpoint)
- **Why SFT over Base/Instruct:** SFT knows how to converse but hasn't been RL-aligned into a stiff corporate assistant — clean slate for personality transfer
- **Why SFT over Instruct/Final:** Avoids fighting against existing RL alignment
- **Architecture:** Standard `LlamaForCausalLM` — broad ecosystem support
- **Compute fit:** QLoRA 4-bit fits comfortably in 16GB VRAM

### Finetuning pipeline

A complete QLoRA pipeline has been built on the `finetuning` branch:

| Script | Purpose |
|--------|---------|
| `train.py` | QLoRA training with TRL SFTTrainer (4-bit NF4, LoRA r=32) |
| `merge.py` | Merge LoRA adapter into base model |
| `inference.py` | Interactive chat test (merged or adapter mode) |
| `convert_gguf.py` | Export to GGUF for llama.cpp / Ollama / LM Studio |

### Personality models surveyed

Several existing 1-3B models with distinct personality/"vibe" were identified as references:

| Model | Params | Vibe |
|-------|--------|------|
| PinkPixel/Snarkle-2B | 2B | Sarcastic, biting wit |
| PinkPixel/Pip-2B | 2B | Ultra-enthusiastic, joyful |
| juiceb0xc0de/bella-bartender-heretic-3b | 3B | Raw personality, single human voice |
| SicariusSicariiStuff/Nano_Imp_1B | 1B | World's first coherent 1B roleplay model |
| Verdugie/Opus-Candid-Lite-4B-P | 4B | Anti-sycophantic, density-optimized |

These serve as proof-of-concept for what's possible at small scale and as methodology references.

### Next steps

1. Collect GPT-4o conversation data (500-5000 conversations per @AonzOG's estimate)
2. Format as JSONL in `data/` (gitignored)
3. First training run on MiniCPM5-1B-SFT
4. Evaluate with "vibe benchmark" (still to be defined — see section 3 above)
5. Scale to Qwen3.5-2B once methodology is proven
