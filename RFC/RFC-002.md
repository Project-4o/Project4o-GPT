# RFC-002: Open-GPT-4o Model Family Roadmap

- **Status:** Under Discussion — Pragmatic small-model track in progress
- **Origin:** [Issue #2](https://github.com/Project-4o/Project4o-GPT/issues/2)
- **Author:** [@AonzOG](https://github.com/AonzOG)
- **Maintainer response:** [@bouclem](https://github.com/bouclem) (project owner)

---

## Summary

@AonzOG proposes expanding Project-4o beyond personality-only fine-tuning into a full open GPT-4o-class omni-modal model family. The proposal covers a four-stage model-size ladder, a multimodal architecture, a training pipeline, and supporting tooling (AutoResearch, LLM Wiki).

@bouclem (project owner) responded with a critical constraint: the project currently has **no compute budget** — an AMD ROCm GPU with 16GB VRAM and no money for better hardware.

Nothing is decided yet. This RFC captures the proposal and the compute reality to frame community discussion.

---

## The Proposal

### Model-size ladder

| Stage | Model | Total Params | Active Params | Context |
|-------|-------|-------------|---------------|---------|
| 1 | Open-GPT-4o-Mini-8B-Dense | 8B-9B | 8B-9B | 32K → 128K |
| 2 | Open-GPT-4o-Mini-A8B-MoE | 40B-80B | ~8B | 128K |
| 3 | Open-GPT-4o-120B/A10B-MoE | 100B-130B | 10B-15B | 128K-256K |
| 4 | Open-GPT-4o-200B-MoE | 180B-220B | 16B-24B | 256K |

The flagship target is a ~200B MoE model aiming for GPT-4o-level benchmark equivalence.

### Tokenisation

The proposal stresses that GPT-4o/o200k-style tokenisation must be chosen **before** pre-training. Swapping tokenizers after training breaks learned token embeddings.

Proposed order:
1. Choose GPT-4o/o200k-style text tokenisation
2. Add Project-4o multimodal special tokens
3. Resize embedding matrix and output head
4. Build data pipeline around this vocabulary
5. Begin pre-training
6. Use AutoResearch to optimise training only after tokenisation is fixed

### Training pipeline (proposed)

**Pre-training:** text → code/math/science → multimodal (vision, audio, video) → tool traces

**Post-training:** SFT → multimodal instruction → GPT-4o-style fine-tuning → preference optimisation → RLVR → tool-use → voice interaction → personality tuning → safety → regression repair

**AutoResearch:** automated experiment loops for both pre-training and post-training, with reviewable diffs and reproducible configs. Not unsupervised rewrites.

**LLM Wiki:** durable project memory — architecture decisions, experiment logs, failed experiments, benchmark results, training recipes.

### Benchmark targets (proposed)

- **Text/reasoning:** MMLU-Pro, GPQA Diamond, AIME, MATH, HumanEval, MBPP, SWE-bench, IFEval, BFCL
- **Vision-language:** MMMU, MathVista, OCRBench, ChartQA, DocVQA, TextVQA, RealWorldQA
- **Audio:** WER, speech translation, spoken QA, streaming latency, turn-taking
- **Generation:** text-to-image faithfulness, image self-critique, 3D asset quality
- **Project-4o interaction:** conversation naturalness, personality consistency, roleplay coherence, emotional tone control

## Maintainer Response

@bouclem (project owner) raised a critical constraint:

> there is kind of problem: GPU.
> - have AMD ROCm gpu, even if it can finetune or train its slower
> - 16GB of vram, this is kind of the most of the problem
> - no money
>   - like no money to buy better GPU

This means the full-scale roadmap as proposed may not be feasible with current resources. The community needs to discuss how to reconcile the ambition of the proposal with the reality of available compute.

## Progress Update (September 2026)

While the full-scale roadmap remains aspirational, a pragmatic small-model track is now in progress on the `finetuning` branch:

- **Base model selected:** `openbmb/MiniCPM5-1B-SFT` (1B params, SFT checkpoint, LlamaForCausalLM architecture)
- **Method:** QLoRA (4-bit NF4 + LoRA r=32) on 16GB AMD ROCm GPU
- **Pipeline built:** `train.py` → `merge.py` → `inference.py` → `convert_gguf.py`
- **Goal:** Prove personality fine-tuning methodology at 1B scale before scaling up

This aligns with @AonzOG's suggestion to "start small" and @bouclem's compute reality. The 1B model is a proving ground — if the vibe/personality transfer works at this scale, the methodology can be applied to larger models (Qwen3.5-2B, 3B, and eventually the 8B+ ladder proposed above) as compute becomes available.

The full-scale roadmap (Stages 1-4) remains the long-term vision. Community contributions of compute, data, or expertise toward any stage are welcome.

## Open Questions for Discussion

1. Should Project-4o create a separate `open-gpt-4o-core` branch for the full-model track?
2. Should the first serious target be 8B dense or A8B MoE?
3. Should GPT-4o/o200k-style tokenisation be canonical from the beginning?
4. What multimodal special-token format should be standardised?
5. Should the first visual encoder be CLIP ViT-B/32, SigLIP, InternViT, or another encoder?
6. How should MoE router adaptation be trained for visual and audio tokens?
7. Should Shap-E and image diffusion be external tools first, then later native latent-output branches?
8. Which public GPT-4o-style datasets are legally reusable?
9. Which public GPT-4o output/distillation datasets are legally reusable?
10. How should LLM Wiki be integrated into AutoResearch?
11. What benchmark threshold qualifies a model as Open-GPT-4o-Mini? As Open-GPT-4o?
12. What compute pool is required for each milestone, and how can the community pool resources?
13. Should the 200B MoE teacher be trained before distilling the A8B model, or should both be developed in parallel?
14. Can the Project-4o personality goal be preserved during high-capability post-training?
15. **How does the project proceed with 16GB VRAM and no budget? What can be done at this scale?**
